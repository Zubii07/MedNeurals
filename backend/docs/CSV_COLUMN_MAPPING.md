# CSV → DB column mapping (Phase 2)

Every DB column is the CSV header converted to snake_case (lower-case, same words). Phase 5 feature
queries use SQL aliases to give `features.py` / `mednerals_ml.py` the original names back.

## Conversion rules
| CSV value | DB type | Import (Phase 3) | Back to ML format (Phase 5) |
|---|---|---|---|
| `Y` / `N` flags | `boolean` | `Y`→true, `N`→false | `CASE WHEN x THEN 'Y' ELSE 'N' END` if needed |
| `0` / `1` flags (`is_stockout`, `is_emergency`, calendar flags) | `boolean` | `1`→true, `0`→false | `x::int` |
| dates | `date` | ISO `yyyy-mm-dd`; **`calendar.date` is `dd/mm/yyyy`** | as is |
| `purchase_orders.lead_time_days` (float in CSV because of blanks) | `integer`, nullable | round to int, blank→NULL | as is |

Surrogate keys not in the CSVs: `demand.id`, `daily_inventory.id`, `purchase_orders.id`,
`stock_transfers.id`, `uploads.*` (all generated by the DB).

Phase 5 example (`build_weekly_demand` input):
```sql
SELECT demand_date AS "Demand_Date", store_id AS "Store_ID", item_id AS "Item_ID", demand_quantity AS "Demand_Quantity"
FROM demand WHERE demand_date <= :cutoff
```

## Import (Phase 3)
Code: `app/services/csv_import.py`. Entry points: `python -m scripts.import_csv --all [--cutoff YYYY-MM-DD]`
(run from `backend/`) and `POST /data/import` (multipart: `dataset`, `file`, optional `cutoff`).

- **Order:** hospitals, categories, units_of_measure, **stores, departments** (departments.primary_store_id → stores),
  medical_items, suppliers, supplier_items, item_department_usage, calendar, demand, daily_inventory,
  purchase_orders, stock_transfers, stockout_events.
- **Validation (pandas):** required headers; required values; dates; Y/N and 0/1 flags; numbers ≥ 0 and whole numbers
  for integer columns; string length; FK ids exist in the DB; duplicate unique keys inside the file (first copy kept);
  date order (end ≥ start, arrival ≥ transfer, expected/receipt ≥ order, contract end ≥ start).
  Rejected rows are written to `import_reports/<upload_id>_<dataset>_rejected.csv` with `row_number` and `reject_reason`.
- **Load:** COPY into a temp table, then `INSERT … ON CONFLICT`. DO UPDATE (changed rows only) for master tables
  and purchase_orders; DO NOTHING for calendar, demand, daily_inventory, stock_transfers, stockout_events.
- **Cutoff:** rows dated after the cutoff are skipped (`uploads.rows_skipped`), by `demand_date`, `date`,
  `order_date`, `transfer_date`, `start_date`. Masters and calendar ignore it. Purchase orders received after the
  cutoff are stored as they were on the cutoff (`status='Open'`, no receipt_date/lead_time_days, accepted_quantity 0);
  re-importing purchase_orders.csv later updates them to Received.
- Every import is a row in `uploads` (status `completed` / `partial` (some rows rejected) / `failed`).

## Runtime feature inputs (Phase 5)
Code: `app/services/feature_inputs.py`. `load_feature_inputs(conn, data_cutoff_date)` returns the source DataFrames for
`app/ml/features.py`; every query reads only rows dated on or before the prediction date (latest Monday ≤ cutoff).

| Query | Feeds | Columns returned |
|---|---|---|
| `demand_history` | `build_weekly_demand` | `Demand_Date`, `Store_ID`, `Item_ID`, `Demand_Quantity` |
| `inventory_history` | `build_stockout_snapshots(inventory)` | `date`, `store_id`, `item_id`, `demand_qty`, `closing_qty`, `on_order_qty`, `is_stockout` (0/1) |
| `transfer_history` | `build_stockout_snapshots(transfers)` | `transfer_date`, `to_store_id`, `item_id`, `shipped_qty` |
| `purchase_order_history` | `build_stockout_snapshots(purchase_orders)` | `purchase_order_id`, `supplier_id`, `item_id`, `order_date`, `expected_delivery_date`, `receipt_date`, `lead_time_days`, `ordered_quantity`, `is_emergency` (0/1) |
| `supplier_item_list` | `build_stockout_snapshots(supplier_items)` | `Item_ID`, `Supplier_ID`, `Preferred_Supplier_Flag` (Y/N) |

Purchase orders: only `order_date ≤ prediction date`; a receipt after the prediction date is returned as NULL
`receipt_date` / `lead_time_days` (the PO was still open then). Check: `python -m scripts.check_feature_inputs --cutoff 2025-11-30`.
